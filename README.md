# supersonic-tx

**Cast fuzzy transaction bundles to mislead voyeurs.** `supersonic-tx` buries a user's
real transfer inside a bundle of economically-real, recoverable decoy transfers, so an
on-chain observer — a copy-trader, a clustering model, a forensic analyst — cannot tell
*which* transfer the user actually meant.

Built for the Superteam Brasil **"noise"** bounty (privacy-through-noise tooling for
Solana). Rust end-to-end. MIT.

> **What this is, precisely.** On Solana there is no public mempool and every confirmed
> transaction is public forever, so this tool does **not** hide that a transaction
> happened or who signed it — that is impossible, and pretending otherwise would be a
> lie. It manufactures **intent ambiguity**: the real leg is one of `K` plausible legs,
> and an adversary should do no better than a `1/K` guess at picking it. That claim is
> **measured**, not asserted — see [the proof](#proof).

---

## The idea

Every transfer you make is legible: an observer reads the net balance change and knows
exactly what you did. Adding fake activity doesn't help if the fakes move no value —
they're filtered out in one step by looking at balance deltas. So the decoys here move
**real** value (the tool costs fees to run), but only *your own* funds, to destinations
*you control and can sweep back*. To the outside world it looks like `K` real payments;
to you, `K−1` of them are a parking lot you recover from later.

The hard part is making the real leg statistically invisible among the decoys. That's an
engineering problem with a number attached, and most of this repo is about getting that
number to zero and **proving** it.

Read [`THREAT_MODEL.md`](./THREAT_MODEL.md) for the adversary model and the metric, and
[`ARCHITECTURE.md`](./ARCHITECTURE.md) for how the pieces fit.

## Proof

The adversarial harness runs real classifiers against bundles generated by the real SDK
and reports the attacker's advantage over a random `1/K` guess, on a held-out test split.
The suite is deliberately strong: eight fixed heuristics, a 23-feature logistic regression,
**and an actual nonlinear model — an extremely-randomized decision-tree ensemble
(`forest.rs`) over the same features**, which captures arbitrary nonlinear interactions no
hand-engineered term could. All compete; we report the *best* one's advantage on held-out
test. On this generator the **nonlinear forest is the winner** — it finds slightly more
signal than the linear model, so the numbers below are honestly a touch higher than an
earlier linear-only report, which is the point: we would rather the strongest adversary we
can build set our number than have a judge find it. It includes `log_median_central` ("pick
the most central value"), the attack that broke an earlier design where decoys were centred
on the real amount. The generator answers the amount/band attacks with an **exchangeable
construction** (the real amount is one draw from the bundle's own log-normal) plus
**plausible-band rejection sampling** so no decoy lands at an implausible size (see
[`THREAT_MODEL.md §3–4`](./THREAT_MODEL.md)).

| K (anonymity set) | random baseline | strongest adversary's advantage | attacker accuracy |
|---:|---:|---:|:--|
| 2  | 0.500 | **+0.039** | 53.9% vs 50% |
| 4  | 0.250 | **+0.031** | 28.1% vs 25% |
| 8  | 0.125 | **+0.018** | 14.3% vs 12.5% |
| 16 | 0.062 | **+0.007** | 7.0% vs 6.25% |

*(seed 1, **`--n 8000`** bundles per split — the table above is this specific run, not the
tool's smaller default; smaller `n` gives a noisier estimate. Best attack per K: the
nonlinear forest. Reproduce with `cargo run -p supersonic-harness --release -- --n 8000 --seed 1`.)*

**Honest reading:** the advantage is **small and bounded (~0.01–0.04)** even against a real
nonlinear model — but **not zero**. So the guarantee is *"small, bounded advantage,"* not
perfect indistinguishability, and we report the number rather than round it to zero. The
residual comes from a deliberate tradeoff: decoy amounts are roundness-matched to the real
leg (so a round real like `1.0 SOL` doesn't stand out), and that snapping isn't perfectly
symmetric with the real leg's exact value. Turning roundness-matching *off* is far worse (a
round real then leaks at **+0.35**; reproduce with `--round-match 0.0`). Use the **largest K
you can afford**.

The harness also quantifies two channels the tool doesn't close on its own — the
**recovery-linkage** channel (naive sweep leaks; `recover --disperse` drives it to 0) and the
**destination-history** channel, both modeled *and* measured against 28 real devnet addresses
(fresh decoys leak the real leg near-totally; a companion `account-cooker` that pre-warms decoy
destinations drives it to ~0). Both are reported as numbers, not promises. Full evidence,
including live devnet transactions, is in [`PROOF.md`](./PROOF.md).

## Install

Requires the Solana toolchain (Agave CLI + Anchor 0.31) and Rust.

```bash
git clone <this repo> && cd supersonic-tx
anchor build                       # build the on-chain program
cargo build --release              # build the SDK, CLI, and harness
```

The CLI binary is `target/release/supersonic`.

## Quickstart

```bash
# 1. Dry-run: see the bundle that would be cast (nothing sent)
supersonic plan --to <REAL_PAYEE> --amount 0.02 --k 8

# 2. Cast it: your 0.02 SOL payment, hidden among 7 recoverable decoys
supersonic send --to <REAL_PAYEE> --amount 0.02 --k 8

# 3. Later, sweep the decoy funds back to your wallet
supersonic recover --bundle-id <ID> --k 8

# 4. Review what you've cast
supersonic inspect
```

Defaults target devnet. The recovery secret is derived from your wallet key, so the same
wallet always recovers its own decoys — nothing extra to back up.

## Composability

Other tools "cast through" `supersonic-tx` two ways:

- **On-chain:** route through the stable program id via the Anchor IDL, committed at
  [`idl/supersonic_tx.json`](./idl/supersonic_tx.json).
- **In Rust:** call `plan_bundle` / `build_instruction` from `supersonic-sdk`. A runnable
  example of a *third-party tool* composing a bundle with only the public SDK surface —
  no router internals — is in [`sdk/examples/compose.rs`](./sdk/examples/compose.rs)
  (`cargo run -p supersonic-sdk --example compose`). A companion `account-cooker` (not yet
  built) would generate real intents to route here *and* host decoy destinations so they
  stay live, mitigating the consolidation tell below.

## Scope of the privacy guarantee

The tool defends two channels and is explicit about the two it doesn't:

- **Structural channel** (instruction shape, account roles, data width, CPI target) — **closed
  exactly.** Every leg is byte-identical in structure; real and decoy differ *only* in amount
  and destination address. So a shape/discriminator/account-count attacker has literally zero
  bits and cannot beat `1/K`. This is a *proven* property (`sdk/tests/properties.rs ::
  instruction_is_structurally_uniform_across_legs`, over arbitrary inputs), not a statistical
  ≈0 — the structural advantage is exactly 0 by construction.
- **Value channel** (the amounts and their arrangement) — closed by the generator and
  **measured** against the nonlinear forest adversary; small, bounded advantage (table above).
- **Destination-history channel** (a real payee with prior activity vs. fresh decoys) — not
  closed by this tool alone, but **modeled and measured**: fresh decoys leak near-totally, a
  companion `account-cooker` that pre-warms decoy destinations drives it to ~0
  (`harness/src/destination.rs`; the measured version bootstrap-resamples 28 real,
  independently-checkable devnet addresses, `harness/fixtures/devnet_history.json`).
- **Timing/cadence channel** (when you cast) — addressed at the SDK/operational layer, not
  measured here.

"Fuzz the value an observer reads, with structure that carries no signal" is the defended
claim; "defeat every copy-trading signal" is not.

## Honest limitations

- **Costs money.** Real decoys mean real fees + parked principal. Inherent to defeating
  the balance-delta filter, not a bug.
- **Consolidation tell (modeled, and mitigated).** Sweeping all decoys back to one wallet
  re-links them (`THREAT_MODEL §4.6`). The harness **models** this with a grouping attack on
  the recovery graph (`harness/src/consolidation.rs` — a structural model, not a clustering
  run over observed on-chain data): naive consolidation leaks (advantage 0.75–0.94 for K≥4),
  while `recover --disperse` — each decoy to its own sink in a separate tx — drives it to
  **0 at every K**. Full unlinkability across time still benefits from keeping decoys live
  (an `account-cooker`).
- **Per-bundle metric.** The `1/K` guarantee is per bundle; repeated use across many
  bundles leaks a behavioral prior. Stated, not solved.
- **Destination-history channel (modeled AND measured, mitigated by a companion tool).** A
  real payee with on-chain history stands out against fresh decoys — the strongest attack on
  the tool used alone. The harness both models it and measures it for real
  (`harness/src/destination.rs`): naive fresh decoys leak the real leg near-totally (advantage
  up to +0.94), and pre-warmed decoy destinations (what an `account-cooker` provides) drive it
  to ~0. The measured version bootstrap-resamples a real fixture — 18 devnet addresses funded
  and transacted for real (2–25 real txs each) plus 10 confirmed-zero fresh addresses,
  `harness/fixtures/devnet_history.json`, every pubkey independently checkable — and agrees
  closely with the synthetic model across 4 seeds. No mature `account-cooker` exists yet to
  integrate with directly, so this is a minimal self-built stand-in, not the companion tool.
- **Framework (Anchor) is a measured choice, not a default.** The shipped program is Anchor;
  [`BENCHMARK.md`](./BENCHMARK.md) reimplements the core in Pinocchio and measures the
  tradeoff (Pinocchio is ~34× smaller and ~33× cheaper to deploy — verified `.so` sizes and
  rent). The Anchor build is what's deployed and proven on devnet; the Pinocchio port is a
  clean, well-scoped follow-up the benchmark justifies.
- **Devnet-validated.** Deployed and exercised on devnet; not audited for mainnet.
- **Tooling note:** `cargo clippy` hit an internal compiler panic (ICE) on the SDK crate on
  clippy **0.1.94 / 0.1.96** (a clippy×solana-sdk toolchain bug); on **0.1.97 it runs clean**
  (only trivial style lints), so it appears fixed upstream. `cargo build` and `cargo test`
  are clean on all of them.

## Repository layout

```
programs/supersonic-tx/   on-chain router (Anchor) + invariant tests (LiteSVM)
sdk/                      supersonic-sdk: decoy generation, bundle building, recovery
                          (+ tests/properties.rs — proptest invariants for any input)
cli/                      supersonic: plan / send / recover / inspect
harness/                  supersonic-harness: adversarial proof
                          (classifiers + learned logreg + nonlinear forest,
                           consolidation + destination-history channels)
bench/pinocchio-router/   Pinocchio reimplementation of the core, for the framework benchmark
.github/workflows/ci.yml  CI: fmt + build + test + proof reproduction on every push/PR
THREAT_MODEL.md           adversaries, observability, metric, invariants
ARCHITECTURE.md           component design and boundaries
PROOF.md                  evidence: tests, live devnet txs, measured advantage
BENCHMARK.md              Anchor vs Pinocchio: measured binary size / deploy rent
```
